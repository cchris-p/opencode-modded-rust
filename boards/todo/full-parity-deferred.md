# Full parity deferred

## Summary

Full parity with the current OpenCode workflow is intentionally deferred.

## Why this exists

The current product goal is a serious personal daily-driver for a narrow workflow with the core Rust architecture in place. Broad parity would expand scope too early and slow down the core runtime design.

## Done when

- V1 through V3 have produced enough real usage data to identify which parts of parity are actually valuable.
- A feature-by-feature adoption plan exists instead of a blanket parity goal.

## Notes

- This item should remain deferred until the core product is stable enough to judge gaps from real use.
