# V2

## Goal

Improve reliability on larger multi-step work without broadening scope prematurely.

## Why this version exists

V2 exists to extend the V1 daily-driver into more demanding task chains while preserving the same architectural discipline.

## Required capabilities

- stronger task decomposition
- better context assembly and state transitions
- more dependable reviewer and repair loops
- better repository discovery before implementation
- early `ScopeMux` integration if it is mature enough to improve retrieval quality

## Explicit non-goals

- full OpenCode parity
- desktop app support
- MCP
- broad ecosystem completeness unrelated to reliability gains

## What V2 adds beyond V1

- more reliable multi-step work inside one repository session
- stronger repair behavior after failed attempts
- cleaner handoff between planning, execution, and review
- retrieval abstractions that can absorb `ScopeMux` when ready

## What is still missing after V2

- wide feature parity with the reference line
- advanced graph-driven planning beyond what is needed for practical reliability
- broader interface and distribution surfaces

## Success gate

V2 succeeds when the runtime handles larger task chains more consistently while preserving the V1 architectural discipline.

## Dependencies

- `ScopeMux` is an early integration target, not a V1 requirement.
- If `ScopeMux` is not ready, the runtime should preserve the abstraction boundary needed to integrate it later.
